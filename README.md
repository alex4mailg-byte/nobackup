# nobackup.org — сайт книги «Резервной копии нет»

Полнотекстовый сайт книги. Текст берётся сборкой прямо с Zenodo по общему DOI `10.5281/zenodo.22336634`, режется `kniga/narezka.py` в `src/` и собирается программой **mdBook**. Папки `src/` в репозитории нет: она порождаемая.

## Что здесь есть

- **Глава — страница, раздел — якорь.** У каждого §N.M собственный адрес вида `gl-11.html#s11-3`.
- **Больше девятисот ссылок §N.M внутри текста живые.**
- **Поиск по всему тексту** — встроенный, работает без сервера.
- Оглавление слева, тёмная тема, печать одной страницей.
- `src/CNAME` — свой домен `nobackup.org`.

## Как собрать у себя

```
curl -sSL -o mdbook.tar.gz https://github.com/rust-lang/mdBook/releases/download/v0.4.40/mdbook-v0.4.40-x86_64-unknown-linux-gnu.tar.gz
tar xzf mdbook.tar.gz
python3 kniga/narezka.py путь/к/книге.md src
./mdbook build      # соберёт в book/
./mdbook serve      # посмотреть на localhost:3000
```

## Выкладка на GitHub Pages

1. Создать репозиторий, положить содержимое этой папки, отправить в ветку `main`.
2. **Settings → Pages → Source → GitHub Actions.**
3. Рабочий процесс `.github/workflows/pages.yml` соберёт и выложит сам.
4. **Settings → Pages → Custom domain:** вписать `nobackup.org`, дождаться проверки, включить **Enforce HTTPS**.

## Обновление при новой ревизии

Ничего делать не надо. Выложили новую версию на Zenodo — сборка возьмёт её сама: по расписанию раз в неделю либо сразу по кнопке **Run workflow** во вкладке Actions. Размер и контрольная сумма скачанного файла сверяются до сборки; не сошлись — сборка падает.

Правки прямо в `src/` бессмысленны: папка стирается перед каждой нарезкой.

## Заглавие

С ревизии 34 книга называется «Резервной копии нет», прежнее заглавие ушло в подзаголовок. `kniga/narezka.py` знает оба заголовка первого уровня, поэтому собирает и старые ревизии тоже.

## Счётчик

Яндекс.Метрика, счётчик 112817249, один на обе книги. Код стоит в `theme/head.hbs` и `nositeli/theme/head.hbs` вместе с метаописаниями.

## Карта сайта

`sitemap.xml` и `robots.txt` порождаются шагом сборки из готового каталога `book/`, то есть по тому, что действительно собралось. В репозитории их нет.

## Главная страница

`landing/index.html` — оформление и вводный текст главной страницы; `landing/favicon.svg` — значок сайта. После сборки обеих книг выполняется `python3 landing/build.py`: он берёт название, подзаголовок и строку ревизии из `src/title.md`, полученного из проверенного файла Zenodo, сохраняет существующий счётчик Метрики и проверяет ссылки на главы и разделы. Результат записывается в `book/index.html` и `book/title.html`. Главы, поиск и печатная версия остаются результатом mdBook.

Загрузка из Zenodo, сверка размера и MD5, расписание, ручной запуск и поведение при недоступности Zenodo не изменены. Затем прежние шаги сборки добавляют canonical, проверяют описания и формируют карту сайта. Править нужно файлы `landing/`, а не собранные HTML. Текст книги в репозиторий не добавляется.
